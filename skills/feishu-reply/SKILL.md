# 飞书回复规范

## 长度路由（框架自动处理，无需手动拆分）

- ≤3000 字：直接以消息/卡片回复。
- \>3000 字：框架自动把正文转成 HTML 文件发送（outputs/&lt;主题&gt;-&lt;日期&gt;.html），并附简短摘要。
- 因此长回答不要压缩或截断，整理成带标题/表格的结构化 Markdown 即可。

## 渠道硬限制（写作时必须遵守）

- 不使用 Markdown 图片语法（`![](...)`）——飞书不渲染。
- 不贴超长 URL（带长 token 的链接等）——会被截断或拒绝；给短链或说明获取路径。
- 不输出原始 HTML 标签——卡片按 lark_md 渲染，HTML 会原样显示。

## 表达口径

- 一律简体中文，即使用户发的是英文。
- 结论先行：第一句给答案，再给必要细节与下一步。
- 代码/命令用代码块；对比类信息用表格。
